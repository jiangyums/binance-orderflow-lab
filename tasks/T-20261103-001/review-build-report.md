## 发现

### P1 — 生命周期主链仍将非代码任务导向测试线

`docs/management/13-task-model.md` §7.3 主链仍写作 `build-reviewed-approved → build-verified → build-verified-approved`（现行第 448 行）；同节常见分支仍写「`build-reviewed-approved → build-verified`（审计通过，进入测试阶段）」且没有 `has_code` 条件（第 465 行）。这与 §2.3／§3.2／§7.2 中仅 `has_code = true` 进入测试线、`has_code = false` 在 `build-reviewed-approved` 结束的规则相冲突。读者依 §7.3 执行仍会把非代码任务送入测试线，核心目标未能在整个任务生命周期规则中一致成立。

该缺口同时使 J-6 未通过：按设计规定的扫描范围重跑，结果为 26 个 Markdown 文件、61 个命中行及 84 个行-检索词命中对；上述 §7.3 命中行既未携带 `has_code` 条件，也未引用 §5.2／§7.2，且 §7.3 不在设计 §4 变更矩阵或「不改清单」中。故台账所记「J-6 按上述口径闭合」及「矩阵外未覆盖命中 0」与实际扫描结果不符。

### P2 — 附录 A 仍以单一「全局终态」描述旧状态映射

`docs/management/13-task-model.md` 附录 A 仍将旧词汇 `completed` 映射为 `build-verified-approved` 并标注「全局终态」，将 `verified` 映射为同一状态（现行第 621–622 行）。正文已定义两种按 `has_code` 区分的终态，但附录没有标明该映射仅适用于旧状态迁移语境，也没有交叉引用新规则。设计 §9 已登记此处仅靠读者推断与 §7.2 一致；当前文本仍可能使读者把单一旧映射误作新规则下的唯一终态。

此外，`docs/management/14-responsibility-boundaries.md` §11 本次变更记录将 `13-task-model.md` 附录 A 列入修改对象，但交付提交未修改该附录，记录范围与实际差异不一致。

## 3. 命名与路径规则

统一式：`tasks/T-YYYYMMDD-NNN/<阶段>-approval-report.md`。`<阶段>` 取值由**审批点**（状态转移的起点态）决定，与四态结论无关：

| 审批点（状态转移） | `<阶段>` | 文件名 |
|---|---|---|
| `proposed-reviewed → proposed-{approved\|rejected\|blocked\|deferred}` | `proposal` | `proposal-approval-report.md` |
| `designed-reviewed → designed-{...}` | `design` | `design-approval-report.md` |
| `build-reviewed → build-reviewed-{...}` | `build-reviewed` | `build-reviewed-approval-report.md` |
| `build-verified → build-verified-{...}` | `build-verified` | `build-verified-approval-report.md` |

派生规则（全部复用既存条款，不新立机制）：

- **每审批段一份**：四态结论共用该段同名文件。既存实践与此一致——`design-approval-report.md` 曾承载 `designed-blocked`（台账 `T-20261020-001.md:25`），后承载 `designed-approved`（`8c9670f`）。
- **同段重审**（如 `*-blocked` 后转 `*-approved`）：在原文件覆盖修订，版本历史由 Git 保留（`13` §6.2「返工采用同文件覆盖」）；不新建 `*-2.md`。
- **与台账记录行的时序**：同一次提交内（`15` §5.1 一次状态转移＝一次提交；报告与台账行同属该提交），非两段提交。
- `build-verified` 线在 `13` §6 表现行载体写作 `build-decision.md`（`13:335-337`），与本式并存问题见戊-3。

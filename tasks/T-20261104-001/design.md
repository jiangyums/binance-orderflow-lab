## 2. 形式化定义（设计采用的读法）

符号均由**被引用小节自身派生**，不手数枚举，随文本修订自动跟随：

- `S`：`13` §2.1／§2.2／§2.3 三张表「状态」列的全部取值。本轮实测 `|S| = 23`。
- `ρ: S → 角色`：该状态在所属 §2 表「角色」列的取值（实测 23 行均非空、无重复状态行）。
- `E`：§3.2「主要允许转移」表行（`:152`～`:181`）。本轮实测 `|E| = 30`。
- `R`：§3.4「恢复转移规则」表行（`:214`～`:245`）。本轮实测 `|R| = 32`。
- `A := E ∪ R ∪ { §7.3 常见分支与 §2.1／§2.2 表后说明中以 X → Y 形式列出且 X、Y ∈ S 的转移 }`（**允许转移全集**；本轮实测该并集比 `E ∪ R` 恰好多出 §4.3 列出的缺口边）。
- **执行角色派生规则 D**：对任意 `e ∈ A`，`执行角色(e) := ρ(e 的目标状态)`。
- 置位权 `P(r) := { e ∈ A : ρ(e 的目标状态) = r }`。
- 写入面 `C(r, X) := { §6 交付物表中「状态 = X 且生产者 = r」的行的「载体」列 }`；§6 无 `X` 行时退回 `14` §6.4 的本角色允许落盘文件集。
- **动作集合** `Act(r, X) := { e ∈ P(r) : e 的当前状态 = X } ∪ C(r, X)`。这就是交办件所说「任务推进到的当下的动作」的可判定形制。
- **用户指令的效力**：指令 `u` 不是 `A` 的元素；`u` 的作用域是「在 `Act(本角色, 现态)` 内选择执行哪一个」与「记入台账的信息」，不改变 `A`、不改变 `ρ`、不改变 `P`。
- **越权**：被请求的动作 ∉ `Act(本角色, 现态)`。
- **代为继续（合法形制）**：用户改令免除「停止等待上一流程完成」的义务，但角色的置位取值仍恒为 `P(本角色) ∩ { e ∈ A : e 的当前状态 = 台账现态 }`；该集合为空时，唯一合规动作是 §6 M-1e 的报告义务。
